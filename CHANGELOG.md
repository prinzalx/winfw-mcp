# Changelog

Every release of winfw-mcp, newest first. The version in `Cargo.toml` is the source of truth;
the [development chapter](docs/09-development.md#releases) explains why every milestone is
released and why some versions have no milestone of their own.

The milestone column of an early row names the subject of the release; later rows describe what
changed, because from milestone 11 onwards a release is one concrete step rather than one of the
ten planned headings.

| 0.74.0 | A rule can name several ports. The port field takes a comma-separated list of single ports and ranges — `80, 443, 8080-8090` — behind a new `Ports` newtype, and the wire format did not change: a single value is still written as one value, an absent port is still absent, and only a list is written with commas, so an existing `rules.toml` loads and is written back exactly as before. Each element becomes a filter of its own, because a range cannot live in the `FWP_UINT16_ARRAY` that a list of single ports could have shared, and one route for both shapes is easier to reason about than two; the filter key of such a rule carries the element number, so no key that existed before moved. The list is bounded to 32 elements at parse time, since every element costs a filter, and that bound is separate from the 32 on application matches. Protocol lists were rejected rather than left out: `FWP_UINT8_ARRAY` is ambiguous with a byte array in WFP, and *TCP and UDP* is already expressible by leaving the field out, which means every transport. Port `0` is refused where it used to be accepted. The page takes the list in the dialog, refuses a malformed element before the request, and shows the ports as chips. Eight tests, 269 in all. |

| 0.72.0 | Connections now name the account behind them.
