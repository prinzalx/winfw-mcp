      Help

      A deny always beats an allow, whatever the order of the list. Patterns accept the wildcards * and ?, and one rule can name several applications as a comma-separated list such as C:\test\tool1.exe, C:\test\tool2.exe. A rule can be narrowed to one protocol (tcp, udp, or a number such as 47), one direction, a port, a port range such as 1024-2048 or a comma-separated list of them such as 80, 443, 8080-8090, and a remote address, network such as 192.168.1.0/24 or span such as 10.0.0.1-10.0.0.9 — or a comma-separated list of them such as 10.0.0.5, 192.168.1.0/24, or a remote name in the Dest field such as www.example.com which is resolved when the filters are built and joins the Remote field as a union; a rule that names none of them is about all of them. Every change is written to rules.toml and pushed to the store immediately. A detected application is one no rule speaks about yet; widen its path into a pattern such as C:\\Program Files\\*\\app.exe before you allow or deny it, if you want to cover more than that one file.
